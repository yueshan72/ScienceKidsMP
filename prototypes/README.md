# 「小宇宙科普」可交互原型

这是 M1 缺的那两件交付物：**UI 视觉稿 + 关卡交互原型**。
同时它也是 S2 前端的实现蓝图——大部分 HTML/CSS 可以直接搬进 `.ttml` / `.ttss`。

## ⚠️ 先说清楚这不是什么

**原型 ≠ 小程序。** 原型做完了，不等于 S2 前端做完了。真正的 `.ttml` / `.ttss`
还一行没写——本机没装抖音开发者工具，写出来也跑不起来。这里是**设计交付物**，
不是可上线的代码。

对外汇报时请说「原型已完成」，不要说「前端已完成」。

## 怎么改

### 改配色

只改 `css/tokens.css`。颜色**只允许出现在这个文件里**——`check.py` 的自检 5
就是守这条的。在别处手写一个 `#fff`，主题切换就会失灵，而且是那种
「换个页面才发现某个角落没变色」的失灵。

### 改字号、间距、圆角

也在 `tokens.css`。两套主题的差异**只在 token 上，布局完全共用**。

### 加一个关卡

打开 `js/data.js`，往 `DATA.levels` 里加一条 JSON。**不要改任何 `.js` 代码，
也不要改 HTML。** 需要提供的字段见 `levels` 里已有的两个样例。

`interactionConfig` 的结构定义在 `docs/接口契约.md` §5.1。

## 怎么转成 `.ttml` / `.ttss`

### 单位换算（关键）

原型里写的是 `px`，但**数值上 1px 就等于小程序的 1rpx**。

手机外框内部按 750px 逻辑宽排版（`css/app.css` 的 `.phone` 用 `zoom: .5`
缩放到 375px 的手机观感），所以「28px」在这里和真机上的「28rpx」
占屏幕的比例完全相同。

> 用 `zoom` 而不是 `transform: scale()` 是有原因的：`transform` 不改变元素的
> 布局尺寸，缩放后仍按 750×1624 占位，要把内容裁进手机框就得写死高度 +
> `overflow: hidden`——那样内容会被裁掉且**无法滚动**。`zoom` 会真的改变布局
> 尺寸，于是手机内部可以正常滚动，跟真机一致。
>
> `zoom` 只用于原型外壳，转 `.ttml` 时整段删除，不影响小程序。

**所以转换就是一条命令，数字一个都不用动：**

```bash
sed -i 's/\bpx\b/rpx/g' 你的文件.css
```

转换后搜 `px` 应该是 0 命中，搜 `rpx` 应该只有你需要的那些。

### 需要改写的（约 15%）

| 原型 | 小程序 | 怎么改 |
| --- | --- | --- |
| `data-tap="reset"` + 委托监听 | `bindtap="onReset"` | 逐处改名（`app.js` 的 `actions` 键名一一对应） |
| `class="is-hidden"` 切显隐 | `tt:if="{{...}}"` | 类名切换改成条件渲染 |
| `innerHTML` 拼列表 | `tt:for="{{list}}"` | 改成模板循环 |
| `$('page').className = ...` | 根 view 的 `tt:class` | 一行 |
| `localStorage` | `tt.setStorageSync` 或云函数 | 用契约 §3.1 的 `setAgeGroup` |
| `mockComplete()` | `call('progress','complete',{...})` | 信封结构已经对齐，直接替换 |
| `min-height: 100%` | `min-height: 100vh` | 一行 |
| **弹窗是 `.page` 的兄弟节点** | 移进根 view 内部 | 移进去后 `position: fixed` 即可 |
| 主题 class 挂在 `.phone`（外层容器） | 挂在根 view | 见下方说明 |
| `.phone` / `.phone-screen` 两层外壳 | 删除 | 真机靠 rpx 自适应 + 页面自带滚动 |

**主题 class 为什么挂在外层容器：**
CSS 变量只向下继承。弹窗为了不随内容滚动，被放在了内容区**外面**，
所以主题 class 必须挂到「同时包住内容区和弹窗」的那一层，弹窗才读得到
`--c-surface` / `--c-mask`。挂错会导致**弹窗背景变透明**（这个坑踩过一次）。

转 `.ttml` 时把弹窗移回根 view 内部，主题 class 挂根 view，结构自然成立。

### 可以直接搬的（约 85%）

HTML 结构、所有 CSS、交互引擎的状态机逻辑。**`data.js` 里两个关卡的
`interactionConfig` 一个字符都不用改**，直接入库。

## 自检与测试

两个脚本，都直接跑，不需要装任何东西。

### 结构自检

```bash
python check.py
```

5 项检查，守的是「原型还能不能干净地转成小程序」。任何一条失败都说明结构
已经偏离，越晚改越贵：

1. **引擎里不含关卡语义** —— 守住「加数据就加关卡」
2. **没把 rpx 当单位用** —— 否则转换会出现两种单位
3. **没有 `file://` 下会失败的加载** —— 守住「双击就能打开」
4. **没用会破坏转换的 CSS 特性**（`rem` / `vw` / `grid` / `gap` / `calc` / `@media`）
5. **颜色只出现在 `tokens.css`** —— 守住主题切换

> 用脚本而不是 grep，是因为注释里会提到换算规则，纯 grep 分不清
> 「注释里提了一句」和「真的写错了」。
>
> 自检 3 只检查**真正被页面 `<script>` 引用的文件**——`test_engine.js` 是
> Node 脚本，用 `require` 很正常，不该被判违规。

### 引擎行为测试

```bash
node test_engine.js
```

26 项断言，用最小 DOM 垫片在 Node 里真的把交互状态机驱动一遍，覆盖：
点错（宽容模式）、1 秒自动恢复、同一目标连点不重复计数、通关结算、
通关后不再响应、重置、未知版本的降级、未实现类型的优雅降级。

> 测试用的关卡配置是**编造的通用配置**，故意不含任何真实关卡名——
> 顺带证明了引擎确实不认识具体关卡。

## 已知的契约缺口

写这个原型时撞到 8 处《接口契约》没写死的地方。**这些必须在会签时决议并
回写契约**，否则 S2 前端和 S3 后端会各自假设一套，联调期撞车。

其中 **G7 最严重**：

> `levels` 集合**没有场景/素材字段**。后果是——同为 `click` 类型的两关，
> 舞台会长得一模一样。前端只能写 `if (levelId === 'rocket-1')` 来区分外观，
> 而一旦这么写，契约 §5.1 那个「新增关卡不改代码只加数据」的核心承诺
> **当场失效**。

原型里用 `level.scene` 字段临时兜住了（见 `js/data.js`），但**该字段目前
不在契约里**，需要补进 §4.1 的 `levels` 集合。

完整 8 条与建议决议见：
`../docs/接口契约.md`（待补）或本次会话的计划文件。

## 待补项（本原型未覆盖）

完整清单与定性见 `../docs/接口契约.md` §8「范围边界」。摘要：

- **视频卡片不可点** —— 首页的内容卡片是**静态展示块，没有挂 `data-tap`**，
  点了没反应。这是**流程缺口**：`contents.mediaUrl` 字段在契约里有定义，
  但 `assets/` 是空的（全仓库零素材），没有视频可播。
  打通它依赖 S4 内容生产先做出 3-4 条短视频。
  > 当前状态是「已知且决定暂缓」，不是遗漏。
- **「删除 / 更正 / 撤回同意」入口** —— 《需求文档》§9.1 标为**硬性要求**，
  **S2 必须实现，提审前不能缺**。属「我的」页面，不在本次打样范围。
- **其余 4 类关卡交互**：`drag` / `dragSort` / `connect` / `drop`。
  契约 §5.1 已定义结构，引擎里预留了注册位但未实现。
- **积分体系** —— 已识别，**V1.0 不实现也不占位**。理由见契约 §8.3。

## 已知风险与验证状态

### ✅ 已验证（2026-10-07，抖音开发者工具实测）

**`.ttss` 支持 CSS 变量（`var()`）。** 首页已搬成真 `.ttml`/`.ttss` 并在
开发者工具里跑通，其配色、圆角、间距全部来自 `var()`，渲染正常。

这条原本是最大的未验证风险（整套主题架构压在它上面），现已关闭，
**无需启用降级方案**。「一套布局 + N 套配色」的分层成立。

### ⚠️ 仍未验证

搬到真机后尚未逐一确认的 CSS 特性：

| 特性 | 用在哪 | 状态 |

零规格（已全篇确认）。本原型的取值（含 `--touch-min: 88px`）是**设计提案**，
需评审确认后才能写进契约。
