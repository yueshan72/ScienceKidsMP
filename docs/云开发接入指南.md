# 抖音云开发接入指南（M2 联调用）

> 目标：把 `cloudfunctions/` 的三个云函数部署上去，拿到 `envID` / `serviceID` / `path`，
> 填进 `miniprogram/app.js`，让页面从本地演示数据切到真实云函数。
>
> 代码已经按官方 API 写好，**你只需要在抖音开发者工具里完成部署和配置**。
> 未完成前，`cloud.enabled` 保持 `false`，小程序照常演示（本地数据）。

---

## 0. 前置条件

| 项 | 要求 | 在哪看 |
| --- | --- | --- |
| 抖音开发者工具 | ≥ 4.3.4（当前 4.5.6 可用） | 已装 |
| 基础库 | ≥ 2.70.0.0 | 开发者工具「详情」 |
| 抖音云服务 | 需在开放平台开通；**测试号可能不可用** | 开发者工具是否出现「抖音云」面板 |
| AppID | 真实 AppID（`testAppId` 可用于前端，但云服务通常要求真实应用） | 开放平台控制台 |

> 如果开发者工具里没有「抖音云」面板，通常是 AppID 还是测试号、或个人认证/云服务未开通。
> 先去开放平台完成应用创建与认证，再回来做本指南。

---

## 1. 创建云环境

1. 用开发者工具打开项目（当前是 `miniprogram/` 目录）。
2. 找到「抖音云」面板 → 创建环境。
3. 记下 **环境 ID（envID）**，形如 `env-xxxxxxx`。
4. 记下云函数服务的 **serviceID**（控制台里一串数字/字母）。

> `envID` 和 `serviceID` 都要填进 `app.js`，缺一个 `request.js` 都会报「云环境未配置」。

---

## 2. 部署云函数

本项目是**一个函数服务 + 三个子函数**的结构：

```
cloudfunctions/
├── user/index.js        → 路径 /user/index
├── progress/index.js    → 路径 /progress/index
├── checkin/index.js     → 路径 /checkin/index
└── product/index.js     ❌ V1.0 不部署（精选联盟已移出范围）
```

### 方式 A：开发者工具在线编辑器（推荐给当前环境）

官方文档确认的流程：

1. **抖音云 → 函数服务 → 新建服务**
2. **类型选「云函数」**（不是容器服务）；服务名如 `sciencekids`
3. 等待初始化。平台会先在 **dev 环境**用模板代码发布一次
4. 左侧文件树里建好结构（最多 10 个文件夹 / 50 个 JS 文件）：
   - 根目录：`package.json`（内容见仓库 `cloudfunctions/package.json`）
   - `user/index.js`
   - `progress/index.js`
   - `checkin/index.js`
5. 在 **dev 环境**调试 → 发布 → 自测 → 再灰度到 prod
   ⚠️ **prod 环境不支持代码编辑**，不要直接在 prod 改

> 运行时：官方文档写的是 **Node.js 14 语法 / CommonJS**，本项目的三个函数已按此兼容。
> 依赖只有 `@open-dy/node-server-sdk`，写进服务根目录的 `package.json` 即可。

### 方式 B：本地目录 / 整包上传（如果面板支持）

1. 在「抖音云」→「函数服务」里新建服务（名字随意，如 `sciencekids`）。
2. 把 `cloudfunctions/` 下的 `user` / `progress` / `checkin` 三个目录上传或关联到该服务。
3. 在每个函数目录执行依赖安装（如果面板不自动装）：
   ```bash
   cd cloudfunctions/user && npm install
   cd ../progress && npm install
   cd ../checkin && npm install
   ```
4. 部署三个函数。

### 如果面板要求「一个函数一个服务」

也可以，但每个函数会有自己的 `serviceID`。此时需要把 `app.js` 的配置从单一 `serviceID` 扩展成映射（`request.js` 目前只支持一个 serviceID）。先按推荐做法走；实在不行再改代码。

---

## 3. 核对调用路径

部署完成后，这是**唯一权威的路径来源**：

1. 在「函数服务」列表里找到 `user/index.js`。
2. 右键 → **「复制小程序端调用示例」**。
3. 看示例里的 `path` 和 `serviceID`：
   - 如果 path 是 `/user/index`（或 `/user/`）→ 与代码默认值一致；
   - 如果不一样 → 以示例为准，改 `app.js` 里的 `paths`。
4. 对 `progress`、`checkin` 各做一次。

> 官方路径规则：根目录 `index` → `/index` 或 `/`；`sub/index` → `/sub/index` 或 `/sub/`。

---

## 4. 建集合并设权限

在「抖音云」→「云数据库」里创建以下集合。**所有集合权限设为「仅管理端可读写」**（前端全部经云函数，不直接碰数据库）。

### `users`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | string | 用户唯一标识，建**唯一索引** |
| `ageGroup` | string / null | `3-6` / `6-9` / `9-12` |
| `createdAt` | number | 毫秒时间戳 |

索引：`openid` 唯一。

### `progress`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | string | — |
| `levelId` | string | 关卡 id |
| `topicId` | string | 主题 id（默认 `space`） |
| `status` | string | `done` |
| `stars` | number | 0~3 |
| `completedAt` | number | 毫秒时间戳 |

索引：**`(openid, levelId)` 联合唯一**。这是幂等的唯一保障，必须建。

### `checkins`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | string | — |
| `date` | string | `YYYY-MM-DD`（服务器日期，UTC+8） |

索引：**`(openid, date)` 联合唯一**。

### `badges`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | string | 获得徽章的用户 |
| `badgeId` | string | 如 `badge_space` |
| `name` | string | 徽章名 |
| `icon` | string | emoji / URL |
| `earnedAt` | number | 毫秒时间戳 |

索引：`(openid, badgeId)` 唯一（防重复发放）。

### `levels`（可选，建议建）

只用于统计 `totalLevels` 和徽章判定。V1.0 内容仍在客户端静态维护，这里放两条“计数用”记录即可：

| `_id` | `topicId` | `name` | `order` | `ageGroup` |
| --- | --- | --- | --- | --- |
| `rocket-1` | `space` | 火箭发射 | 1 | `3-6` |
| `meteor-2` | `space` | 陨石坑 | 2 | `9-12` |

> 不建也能跑：`progress` 云函数内置了 `TOPIC_LEVEL_COUNT = { space: 2 }` 作为兜底；
> 但 `getProfile.stats.totalLevels` 会返回 0，前端以本地关卡数为准。

## 5. 填配置

打开 `miniprogram/app.js`，把 `globalData.cloud` 填上：

```js
cloud: {
  enabled: true,                    // 改成 true
  envID: 'env-xxxxxxxx',            // 第 1 步拿到的环境 ID
  serviceID: 'xxxxxxxx',            // 第 1 步拿到的函数服务 ID
  paths: {
    user: '/user/index',            // 以第 3 步复制的示例为准
    progress: '/progress/index',
    checkin: '/checkin/index'
  }
}
```

保存后重新编译。`request.js` 会自动用 `tt.createCloud` + `cloud.callContainer` 调云函数。

> 如果只是给老师演示、还没部署云，保持 `enabled: false` 即可，功能全部走本地数据。

## 6. 联调验收清单

在真机或模拟器上依次走：

- [ ] 首次进入弹出「监护人同意」，拒绝后不展示内容、不采集数据
- [ ] 同意后选择年龄段，首页内容按年龄过滤
- [ ] 进入关卡，完成互动后出现星星；重复点同一目标不加星
- [ ] 返回主题页，关卡显示「已通关」；「我的」页进度 +1
- [ ] 完成第二关后获得「太空探索者」徽章
- [ ] 「我的」页打卡，连续天数 +1；同一天重复打卡提示"已经打过卡啦"
- [ ] 「我的」→ 更正年龄段，首页主题与内容随之变化
- [ ] 「我的」→ 删除我的数据：确认后数据清空，回到首页要求重新同意
- [ ] 撤回同意：同上，且云端该 openid 的数据被删除
- [ ] 断网或云函数报错时，页面回落到本地数据，不白屏

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `云环境未配置` | `enabled=false` 或 `envID`/`serviceID` 为空 | 检查 `app.js` 配置 |
| `1001 未登录` | 云函数拿到的 `openId` 为空 | 确认从真实小程序环境调用、已登录抖音；不要用 HTTP 裸调 |
| `3001 云数据库读写失败` | 集合不存在 / 权限不对 / 索引未建 | 按第 4 步建集合、设「仅管理端」、建联合唯一索引 |
| `HTTP 404` / 路径错误 | `path` 与部署结构不一致 | 用「复制小程序端调用示例」里的 path |
| 云函数报 `Cannot find module '@open-dy/node-server-sdk'` | 依赖未安装 | 在函数目录 `npm install` 后重新部署 |
| 徽章不发放 | `levels` 集合为空且主题不是 `space` | 检查 `TOPIC_LEVEL_COUNT` 或补 `levels` 记录 |
| 打卡日期不对 | 服务器时区 | 代码已按 UTC+8 计算；如仍异常，检查函数运行环境的时间设置 |
