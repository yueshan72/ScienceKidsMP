# 数据层接口（V1.4 · 本地优先 + 云端双路线）

> **状态**：2026-10-27 生效。
> **云数据库体验权限已通过**，主路线恢复为**文档型数据库 + 三个独立云函数**
> （`user` / `progress` / `checkin`）。
>
> 备选路线：单函数 `/api/index` + 对象存储 TOS。代码、测试与
> [`对象存储后端接入指南.md`](对象存储后端接入指南.md) 均保留；切换时只改
> `app.js` 的 `paths`，不需要改页面或适配器。
>
> 云函数的字段级契约（入参、出参、错误码）仍以
> [`接口契约.md`](接口契约.md) §2–§4 为准，本文只定义**数据层内部接口与切换方式**。

## 1. 分层

```
pages/*.js
   │  只依赖 data-service，不直接调 request.js / 适配器 / 云函数
   ▼
utils/data-service.js          编排：本地先行、云端同步、失败回落
   ├── utils/data-adapters/local-adapter.js   本地实现（离线兜底）
   └── utils/data-adapters/cloud-adapter.js   云端实现（主路线：文档库三函数；TOS 备选）
```

读取与写入分开：

| 方向 | 走哪里 | 原因 |
| --- | --- | --- |
| 读（年龄 / 进度 / 打卡 / 收藏 / 点赞） | `utils/local-state.js` 本地镜像 | 同步读取，无加载态，页面简单 |
| 写（年龄 / 通关 / 打卡 / 删除 / 撤回） | `utils/data-service.js` → 适配器 | 统一入口，切换后端不改页面 |

内容（视频、关卡）是客户端静态数据（`utils/demo-data.js`），不属于数据层，
V1.0 没有 `content` 云函数。

## 2. 模式：`cloud.mode`

配置在 `miniprogram/app.js` 的 `globalData.cloud.mode`：

| 值 | 行为 | 适用场景 |
| --- | --- | --- |
| `'local'` | 只读写手机本地；`request.js` 不初始化，**不发起任何网络请求** | **当前默认**，课堂演示 / 未审批 |
| `'auto'` | 本地先写 → 调云端（主路线：文档库三函数；备选：TOS 单函数）→ 成功用云端结果覆盖，失败保留本地并标记 `offline=true` | **当前默认**（云数据库已通过） |

`mode` 与 `enabled` 的关系：`app.js` 启动时把 `mode === 'auto'` 换算成
`request.configure({ enabled })`。页面与适配器都不直接读 `mode`；
判断「能否用云」统一走 `dataService.cloudEnabled()`。

### 2.1 主路线：文档型数据库（当前）

1. 抖音云控制台建 `users` / `progress` / `checkins` / `badges` 集合，
   权限设为「仅管理端可读写」（见 [`云开发接入指南.md`](云开发接入指南.md) §4）。
2. 建索引：
   - `users`：`openid` 唯一
   - `progress`：`(openid, levelId)` 联合唯一
   - `checkins`：`(openid, date)` 联合唯一
   - `badges`：`(openid, badgeId)` 联合唯一
3. 确认 `user` / `progress` / `checkin` 三个云函数已发布，三条授权路径已加。
4. `app.js` 的 `paths` 保持 `/user/index`、`/progress/index`、`/checkin/index`，
   `mode='auto'`（当前已配好）。
5. 按 [`云开发接入指南.md`](云开发接入指南.md) §6 的清单真机验收。
6. **回滚**：把 `mode` 改回 `'local'` 即可，本地数据仍完整保留。

> 集合建好前，云端调用会失败并自动回落本地（`offline=true`），不影响本地演示。
> 建好后重新编译，再走一遍完整流程即可。

### 2.2 备选路线：对象存储 TOS

1. 抖音云控制台 → 组件中心 → 对象存储 → 启用，确认桶名/地域，生成 AK/SK。
2. 部署 `cloudfunctions/api/`，路径确认是 `/api/index`，加授权路径。
3. 在函数服务「服务设置」配置 `TOS_BUCKET` / `TOS_ACCESS_KEY_ID` /
   `TOS_ACCESS_KEY_SECRET` / `TOS_REGION` / `TOS_ENDPOINT`，重新发布。
4. 把 `app.js` 的 `paths` 三条都改为 `/api/index`；`mode` 保持 `'auto'`。
5. 按 [`对象存储后端接入指南.md`](对象存储后端接入指南.md) §4 验收。
6. **回滚**：`paths` 改回三个旧路径即可，代码不动。

## 3. 适配器接口

`local-adapter.js` 与 `cloud-adapter.js` 必须导出**同名、同形状**的五个方法。
所有方法返回 `Promise`，成功时 resolve 出《接口契约》§3 对应的业务出参；
失败时 reject 出 `{ code, message }`（本地适配器不会 reject）。

云端适配器只做一件事：把方法名映射成 `request.call(name, action, payload)`；
`request.js` 会在 body 里带上 `name`。主路线的三个独立函数会忽略 `name`，
TOS 备选路线的单函数 `/api/index` 则靠 `name` 路由——两种后端共用同一份客户端代码。

| 方法 | 入参 | 成功出参 |
| --- | --- | --- |
| `setAgeGroup(ageGroup)` | `'3-6' \| '6-9' \| '9-12'` | `{ ageGroup }` |
| `completeLevel(levelId, wrongCount, topicId)` | `levelId: string`，`wrongCount: number`，`topicId?: string` | `{ levelId, status, stars, newBadges, isFirstComplete }` |
| `checkin()` | 无 | `{ date, streak, isNew }` |
| `deleteData()` | 无 | `{ deleted: true }` |
| `withdrawConsent()` | 无 | `{ withdrawn: true }` |

`data-service` 在所有写操作的返回上统一附加一个字段：

| 场景 | `offline` |
| --- | --- |
| `mode='local'` | `false` |
| `mode='auto'` 且云端成功 | `false` |
| `mode='auto'` 且云端失败（本地已保留） | `true` |

页面用 `offline` 决定提示文案（如打卡成功的「（本地）」后缀），不参与业务判断。

## 4. 失败语义

| 操作 | 本地写入时机 | 云端失败时 |
| --- | --- | --- |
| `setAgeGroup` | 立即 | **保留**本地，返回 `offline=true` |
| `completeLevel` | 立即 | **保留**本地，返回 `offline=true` |
| `checkin` | 立即 | **保留**本地，返回 `offline=true` |
| `deleteData` | **云端成功之后** | **reject，且本地完全不动** |
| `withdrawConsent` | **云端成功之后** | **reject，且本地完全不动** |

删除 / 撤回之所以是「云端失败就不清本地」，是因为这两项是合规承诺（《需求文档》§9.1）：
如果本地清了、云端没删，用户会误以为数据已全部删除，实际仍留在服务器上。
页面必须把 reject 展示给用户（`mine.js` 已有对应弹窗），不能静默吞掉。

## 5. 数据边界

| 数据 | 本地键 | 当前是否上云 |
| --- | --- | --- |
| 年龄段 | `sci.ageGroup` | 否（接口保留） |
| 闯关进度 / 星星 | `sci.progress` | 否（接口保留） |
| 徽章 | `sci.badges` | 否（接口保留） |
| 打卡记录 | `sci.checkins` | 否（接口保留） |
| 监护人同意 | `sci.consent` | 仅本地 |
| 收藏 / 点赞 | `sci.favorites` / `sci.likes` | **V1.0 仅本地**（既有范围决策，不新增接口） |

`'local'` 模式下小程序**不上传任何用户数据**；「删除我的数据 / 撤回同意」
只清本机存储并重置同意状态，符合「不采集即不处理」的最小化原则。

## 6. 未来接第三种后端

1. 新建 `miniprogram/utils/data-adapters/<name>-adapter.js`，实现上表五个方法；
2. 在 `data-service.js` 增加一个选择分支（当前只有 `local` / `auto` 两条）；
3. 页面代码零改动；读取仍以本地镜像为准，除非同时实现启动时的 `syncDown`；
4. 按 `tests/data-service.test.js` 的方式补一组适配器测试。

> 注意：抖音小程序对 `request` 域名有白名单要求，第三方后端需要备案域名，
> 学生主体通常走不通。这也是本次选择本地优先的原因之一。
