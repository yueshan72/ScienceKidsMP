## 2. 通用约定

### 2.1 调用方式

前端统一经 `miniprogram/utils/request.js` 调云函数，不直接裸调。

> ⚠️ **待 S1 确认**：抖音云开发云函数的调用方式与 `tt.cloud` SDK 的确切 API，需对照抖音官方文档确认后在 `request.js` 中落地。本契约的**入参/出参结构不受调用方式影响**。

### 2.2 统一返回结构

所有云函数**一律返回**下面这个信封，不允许裸返回业务数据：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | `0` 表示成功，非 0 见 §2.3 错误码 |
| `message` | string | 成功时为 `"ok"`；失败时为给用户看的中文提示 |
| `data` | object \| null | 业务数据；失败时为 `null` |

### 2.3 错误码

| code | 含义 | 前端处理 |
| --- | --- | --- |
| `0` | 成功 | — |
| `1001` | 未登录 / openid 失效 | 重新触发授权登录 |
| `1002` | 参数校验失败 | 提示 `message`，不重试 |
| `1003` | 无权限 | 提示，返回上一页 |
| `2001` | 资源不存在（关卡 / 商品被下架） | 提示并刷新列表 |
| `3001` | 云数据库读写失败 | 提示"网络异常，请重试" + 重试 1 次 |
| `5000` | 未知错误 | 提示 + 上报埋点 |

> 待 S1 补充业务专属错误码。

### 2.4 分页规范

所有列表类接口统一用：

- **入参**：`page`（从 1 开始）、`pageSize`（默认 20，上限 50）
- **出参**：`data.list`（数组）、`data.total`（总数）、`data.hasMore`（布尔）

### 2.5 字段与时间规范

- 字段命名：**小驼峰**（`ageGroup`、`levelId`）
- 时间：**毫秒时间戳**（number），不用字符串
- 主键：`_id`（云数据库默认）
- 用户标识：统一用 `openid`，前端**不接触**自增 id

### 2.6 埋点事件命名

按《需求文档》9.5 的 `page_xxx / click_xxx / complete_xxx` 规则。**新增埋点必须登记到 §6 表格**，否则视为无效埋点。

## 3. 云函数清单

> 以下为按《需求文档》第 7 节数据模型推导的**接口骨架**，待 S1 补全字段细节与实现。

### 3.1 `user` —— 登录与用户信息

| 动作 | 入参 | 出参 `data` |
| --- | --- | --- |
| `login` | `{ code }`（抖音登录凭证） | `{ openid, ageGroup, isNew }` |
| `setAgeGroup` | `{ ageGroup: '3-6'\|'6-9'\|'9-12' }` | `{ ageGroup }` |
| `getProfile` | `{}` | `{ openid, ageGroup, badges[], stats }` |

**约束**：
- 首次登录 `ageGroup` 为 `null`，前端按《需求文档》4.1 弹年龄段选择
- ⚠️ **合规**（《需求文档》9.1）：**不得**采集未成年人敏感信息；不采集精确位置与联系方式

### 3.2 `progress` —— 闯关进度

| 动作 | 入参 | 出参 `data` |
| --- | --- | --- |
| `list` | `{ topicId }` | `{ list: [{ levelId, status, completedAt }], total, hasMore }` |
| `complete` | `{ levelId }` | `{ levelId, status, stars, newBadges[] }` |
| `getBadges` | `{}` | `{ list: [{ badgeId, name, earnedAt }] }` |

**约束**：
- `complete` 必须**幂等**——重复调用同一 `levelId` 不重复发星、不重复发徽章
- 徽章发放逻辑放云函数，**前端不可信**（进度与奖励是核心数据）

### 3.3 `checkin` —— 打卡

| 动作 | 入参 | 出参 `data` |
| --- | --- | --- |
| `checkin` | `{}` | `{ date, streak, isNew }` |
| `getStreak` | `{}` | `{ streak, lastDate, calendar[] }` |

**约束**：连续天数由云函数按**服务器日期**判定，不用客户端时间（防改时间刷打卡）。

### 3.4 `product` —— 精选联盟商品

| 动作 | 入参 | 出参 `data` |
| --- | --- | --- |
| `listByContent` | `{ contentId }` | `{ list: [{ productId, name, cover, price, jumpUrl }] }` |
| `listByLevel` | `{ levelId }` | 同上 |

**约束**：
- ⚠️ **合规**（《需求文档》9.1）：带货内容**必须显著标识**，不得诱导性消费引导
- 商品数据来自精选联盟接口，**不自建商品体系**（《开发计划书》第 1 节）
- 接口返回需带 `hasAdMark: true` 之类的标识字段，供前端渲染"广告/推广"标记

## 4. 数据库集合定义

> 按《需求文档》第 7 节数据模型展开，**字段类型与索引待 S1 定稿**。

| 集合 | 对应实体 | 关键字段 |
| --- | --- | --- |
| `users` | 用户 User | `_id`、`openid`、`ageGroup`、`createdAt` |
| `topics` | 主题 Topic | `_id`、`name`、`cover`、`intro` |
| `contents` | 内容 Content | `_id`、`topicId`、`type`(video/experiment)、`title`、`ageGroup`、`sort` |
| `levels` | 关卡 Level | `_id`、`topicId`、`name`、`sciencePoint`、`interactionConfig`、`order` |
| `progress` | 闯关记录 Progress | `_id`、`openid`、`levelId`、`status`、`completedAt` |
| `checkins` | 打卡记录 CheckIn | `_id`、`openid`、`date` |
| `badges` | 徽章 Badge | `_id`、`name`、`condition` |
| `products` | 商品 Product | `_id`、`name`、`cover`、`price`、`commission`、`contentId` |

**索引待补**（S1 定稿）：`users.openid` 唯一索引；`progress` 的 `(openid, levelId)` 联合唯一索引（支撑 §3.2 幂等）；`checkins` 的 `(openid, date)` 唯一索引。

## 6. 埋点事件登记表

> 新增埋点必须登记在此。命名规则 `page_xxx / click_xxx / complete_xxx`（《需求文档》9.5）。

| 事件名 | 触发时机 | 参数 | 对应指标（《需求文档》第 10 节） |
| --- | --- | --- | --- |
| `page_home` | 进入首页 | `ageGroup` | 获客 |
| `page_topic` | 进入主题页 | `topicId` | 互动 |
| `click_video_play` | 点击播放视频 | `contentId` | 获客 |
| `complete_level` | 完成关卡 | `levelId`、`duration` | 互动：关卡完成率 |
| `click_product` | 点击商品位 | `productId`、`contentId` | 变现：商品点击率 |
| `page_checkin` | 完成打卡 | `streak` | 留存：连续打卡率 |
| `login_success` | 登录成功 | `isNew` | 获客：进小程序转化率 |

> 待 S1/S2 补全；埋点上报入口在 `utils/` 中统一封装。
