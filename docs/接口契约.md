## 1. 为什么要有这份文档

原计划 S2 前端（3 周）与 S3 后端（3 周）**完全并行**，若双方各自开工而无人对齐接口，S5 联调（仅 2 周）会被"字段名对不上、返回结构不一致"大量消耗，直接冲击 M2。

**本契约就是那根对齐的基准线**：冻结后两侧照它实现，联调期只做集成验证，不做接口返工。

## 2. 通用约定

### 2.1 调用方式

前端统一经 `miniprogram/utils/request.js` 调云函数，**页面里不得裸调**。

#### ✅ 已确认（抖音官方文档）

| 项 | 内容 |
| --- | --- |
| 云实例入口 | `tt.createCloud({ envID, serviceID })` |
| 基础库要求 | 小程序 **≥ 2.70.0.0** |
| 云数据库 | `await cloud.database()`（**必须加 `await`**；不传 `envID` 时沿用 `createCloud` 的配置） |
| 云托管 | `cloud.callContainer({ path, init })` |
| 本地调试 | 抖音开发者工具 **≥ 4.3.4**；`project.config.json` 需新增 `cloudfunctionRoot` 字段 |

```js
// 已确认的入口写法
const cloud = tt.createCloud({
  envID: 'your-env-id',
  serviceID: 'your-service-id',
});
```

#### 🔴 未确认（最高优先待关闭项）

> **云函数（`callFunction` 类能力）的确切调用方法，本次查证未能确认。**
>
> 原因：抖音开放平台官方文档域名在申报当前网络环境下不可访问；公开检索到的资料仅覆盖 `cloud.database()` 与 `cloud.callContainer()`，**未包含云函数调用示例**。

**⚠️ 现有 `request.js` 的写法是错的**，必须更正：

```js
// ❌ 现有代码（微信写法，抖音云没有 tt.cloud 入口）
tt.cloud.callFunction({ name, data })

// ✅ 待确认（候选写法，**未经证实，不得直接采用**）
//   抖音云实例若支持同名方法，形如：
cloud.callFunction({ name, data })
```

**关闭办法（唯一权威途径）**：

1. 用抖音开发者工具打开本项目
2. 在「抖音云」面板**先部署任意一个云函数**（如 `user`）
3. 面板右键 → **「复制小程序端调用示例」**
4. 把复制到的代码替换进 `request.js`，并把真实写法登记回本节

> **责任人**：后端开发。**关闭时限**：S2 前端开工前必须关闭——否则前端所有网络请求都写不出来。
>
> **缓解**：本契约的**入参 / 出参结构不受调用方式影响**，两侧可先按 §3 并行推进业务逻辑。

### 2.2 统一返回结构

所有云函数**一律返回**下面这个信封，不允许裸返回业务数据：

```json
{ "code": 0, "message": "ok", "data": {} }
```

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `code` | number | 否 | `0` 成功，非 0 见 §2.3 |
| `message` | string | 否 | 成功时为 `"ok"`；失败时为给用户看的中文提示 |
| `data` | object \| null | 是 | 业务数据；失败时为 `null` |

### 2.3 错误码

**分段规则**：`1xxx` 用户与鉴权 ｜ `2xxx` 资源 ｜ `3xxx` 存储与网络 ｜ `4xxx` 业务 ｜ `5xxx` 系统

| code | 含义 | 前端处理 |
| --- | --- | --- |
| `0` | 成功 | — |
| `1001` | 未登录 / openid 失效 | 重新触发授权登录 |
| `1002` | 参数校验失败 | 提示 `message`，不重试 |
| `1003` | 无权限 | 提示，返回上一页 |
| `1004` | 年龄段未选择 | 弹出分龄选择（《需求文档》4.1），选完重试 |
| `2001` | 资源不存在（关卡 / 商品被下架） | 提示并刷新列表 |
| `2002` | 内容不在当前年龄段范围 | 静默跳过该条，不打断浏览 |
| `3001` | 云数据库读写失败 | 提示"网络异常，请重试" + 重试 1 次 |
| `3002` | 云存储 / CDN 不可用 | 提示 + 降级为封面图占位 |
| `4001` | 打卡日期不合法（客户端时间异常） | 提示"请检查手机时间"，不重试 |
| `4002` | 精选联盟接口异常 | 商品位降级为隐藏，**不阻断主流程** |
| `4003` | 商品已下架 | 移除该商品卡片 |
| `5000` | 未知错误 | 提示 + 上报埋点 |

### 2.4 分页规范

所有列表类接口统一用：

- **入参**：`page`（从 1 开始，整数）、`pageSize`（默认 20，上限 50）
- **出参**：`data.list`（数组）、`data.total`（总数）、`data.hasMore`（布尔）

### 2.5 字段与时间规范

- 字段命名：**小驼峰**（`ageGroup`、`levelId`）
- 时间：**毫秒时间戳**（number），不用字符串。**例外**：`date` 类字段（打卡日）用 `YYYY-MM-DD` 字符串
- 主键：`_id`（云数据库默认）
- 用户标识：统一用 `openid`，前端**不接触**自增 id
- 金额：`price` 单位为**分**（整数），避免浮点误差；展示时前端除以 100

### 2.6 埋点事件命名

按《需求文档》9.5 的 `page_xxx / click_xxx / complete_xxx` 规则。**新增埋点必须登记到 §6 表格**，否则视为无效埋点。

### 3.2 `progress` —— 闯关进度

#### `list`

| 方向 | 字段 | 类型 | 必填 | 校验 / 说明 |
| --- | --- | --- | --- | --- |
| 入 | `topicId` | string | ✅ | 非空，否则 `1002` |
| 入 | `page` | number | — | 整数 ≥ 1，默认 1 |
| 入 | `pageSize` | number | — | 整数 1~50，默认 20 |
| 出 | `list` | array | — | 元素 `{ levelId, status, stars, completedAt }` |
| 出 | `total` | number | — | — |
| 出 | `hasMore` | boolean | — | — |

`list` 元素字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `levelId` | string | — |
| `status` | `'todo'` \| `'done'` | 枚举 |
| `stars` | number | **0 ~ 3** |
| `completedAt` | number \| null | 毫秒时间戳，未完成为 `null` |

#### `complete`

| 方向 | 字段 | 类型 | 必填 | 校验 / 说明 |
| --- | --- | --- | --- | --- |
| 入 | `levelId` | string | ✅ | 非空，否则 `1002` |
| 出 | `levelId` | string | — | 回显 |
| 出 | `status` | `'done'` | — | — |
| 出 | `stars` | number | — | 0 ~ 3 |
| 出 | `newBadges` | array | — | 本次新得徽章 id 数组，无为 `[]` |
| 出 | `isFirstComplete` | boolean | — | **本次是否首次通关**，前端据此决定是否播动画 |

**约束（关键）**：
- ✅ **必须幂等**——重复调用同一 `levelId` 不重复发星、不重复发徽章，且**返回 `code: 0`**（幂等命中不算错误）
- 幂等依赖 `progress` 集合 `(openid, levelId)` **联合唯一索引**（见 §4.3）
- 徽章发放逻辑放云函数，**前端不可信**（进度与奖励是核心数据）

#### `getBadges`

| 方向 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 入 | — | — | 无入参 |
| 出 | `list` | array | 元素 `{ badgeId, name, icon, earnedAt }`；未获得的徽章**不返回** |

### 3.3 `checkin` —— 打卡

#### `checkin`

| 方向 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 入 | — | — | 无入参（日期一律取服务器时间） |
| 出 | `date` | string | `YYYY-MM-DD`，**服务器日期** |
| 出 | `streak` | number | 连续天数，≥ 1 |
| 出 | `isNew` | boolean | 今日是否首次打卡（重复调用返回 `false` 且 `code: 0`） |

#### `getStreak`

| 方向 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 入 | — | — | 无入参 |

### 3.4 `product` —— 精选联盟商品

#### `listByContent` / `listByLevel`

| 方向 | 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| 入 | `contentId` \| `levelId` | string | ✅ | 非空，否则 `1002` |
| 出 | `list` | array | — | 元素见下表 |

`list` 元素字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `productId` | string | 精选联盟商品 id |
| `name` | string | 商品名 |
| `cover` | string | 封面图 URL |
| `price` | number | **单位：分**（整数） |
| `jumpUrl` | string | 跳转落地页 / 购物车地址 |
| `hasAdMark` | boolean | **恒为 `true`**，前端须据此渲染"推广"标记 |

**约束**：
- ⚠️ **合规**（《需求文档》9.1）：带货内容**必须显著标识**，不得诱导性、夸大性消费引导
- 商品数据来自精选联盟接口，**不自建商品体系**（《开发计划书》第 1 节）
- 接口异常返回 `4002` 时，前端**降级隐藏商品位，不阻断主流程**

> ### 🔵 范围决策（2026-10-07）：**V1.0 不接入精选联盟**
>
> **决策**：`product` 云函数**不纳入 V1.0 交付范围**；前端保留商品位 UI 与「推广」标识，数据取**静态占位**，点击跳转抖音搜索页。
>
> **理由**：精选联盟准入不是"提交申请等审核"，而是一整套真实商业经营门槛，**学生主体无法满足**：
>
> | 门槛 | 要求 |
> | --- | --- |
> | 店铺主体 | 需营业执照（与店铺主体一致） |
> | 保证金 | 个体工商户 **2000 元** / 企业 **4000 元**，且**0 元入驻不可开通** |
> | 体验分 | ≥ 70 分（需先真实经营攒分） |
> | 营业时长 | 个人店需**满 60 天** |
> | 佣金比例 | ≥ 5% |
>
> 抖音官方《精选联盟平台管理规则》中另有「个人店、个体工商户精选联盟不得准入」的表述，与部分第三方说法冲突，但**没有任何一条指向"学生主体可准入"**。
>
> **本接口保留为「预留契约」**：入参/出参结构照此定义，未来若主体条件具备，可直接实现而无需改动前端。**但 V1.0 不承诺实现，也不依赖它。**
>
> **影响（正面）**：删除了 V1.0 中最大的外生不确定性——原「资质审批周期不可控」风险**不复存在**，因为该路径已确认关闭且不再需要。

### 4.2 权限规则

所有集合统一设为 **「仅管理端可写」**——前端不直接读写云数据库，**全部读写经云函数**。

理由：进度、徽章、打卡是核心数据，前端不可信（同 §3.2 约束）。

### 4.3 索引（S1 定稿）

| 集合 | 索引字段 | 类型 | 支撑 |
| --- | --- | --- | --- |
| `users` | `openid` | **唯一** | §3.1 登录 upsert |
| `progress` | `(openid, levelId)` | **联合唯一** | §3.2 `complete` 幂等 |
| `checkins` | `(openid, date)` | **联合唯一** | §3.3 打卡幂等 |
| `contents` | `(topicId, ageGroup, sort)` | 普通（联合） | §3.2 内容流分龄查询 |
| `levels` | `(topicId, order)` | 普通（联合） | 关卡列表排序 |

> **注意**：`progress` 与 `checkins` 的联合唯一索引是**幂等性的唯一保障**。若索引缺失，并发重复请求会重复发奖——这是必须在 S1 建好、S3 依赖的前置条件。

### 5.1 `interactionConfig` 结构定义（S1 新增）

**设计目标**：用**一套统一结构**描述全部关卡交互，前端只实现一套「解释器」，新增关卡**不改代码只加数据**。

**坐标规范**：所有坐标一律使用 **0~1 归一化值**（相对舞台宽高），避免机型分辨率差异。

#### 顶层结构

```json
{
  "type": "click | drag | dragSort | connect | drop",
  "version": 1,
  "prompt": "点一点，让火箭飞起来！",
  "successText": "发射成功！",
  "failText": "再试一次吧～",
  "props": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | string | ✅ | 交互类型，枚举见下 |
| `version` | number | ✅ | 结构版本，当前 `1`；结构变更时递增，前端按版本兼容 |
| `prompt` | string | ✅ | 给孩子的引导语（**注意用词适龄**） |
| `successText` | string | ✅ | 成功反馈文案 |
| `failText` | string | ✅ | 失败反馈文案 |
| `props` | object | ✅ | 各类型特有配置，见下 |

#### 五类交互的 `props`

**① `click` —— 点击点火**（如：火箭发射）

```json
{
  "targets": [
    { "id": "t1", "label": "点火按钮", "x": 0.5, "y": 0.7, "isCorrect": true },
    { "id": "t2", "label": "装饰", "x": 0.2, "y": 0.4, "isCorrect": false }
  ],
  "requiredHits": 1
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `targets[]` | array | 可点元素，含归一化坐标 |
| `targets[].isCorrect` | boolean | 是否算作正确点击 |
| `requiredHits` | number | 通关所需正确点击数 |

**② `drag` —— 拖拽到目标**（如：拖陨石撞月面）

```json
{
  "draggable": [ { "id": "d1", "label": "陨石", "icon": "url", "startX": 0.2, "startY": 0.2 } ],
  "dropZones": [ { "id": "z1", "x": 0.7, "y": 0.5, "w": 0.2, "h": 0.2, "acceptId": "d1" } ],
  "snapTolerance": 0.05
}
```

**③ `dragSort` —— 拖拽排序**（如：行星排排队）

```json
{
  "items": [
    { "id": "i1", "label": "水星", "correctOrder": 1, "x": 0.5, "y": 0.3 },
    { "id": "i2", "label": "金星", "correctOrder": 2, "x": 0.5, "y": 0.5 }
  ],
  "axis": "y"
}
```

**④ `connect` —— 点击连线**（如：看星座）

```json
{
  "nodes": [ { "id": "n1", "label": "A", "x": 0.3, "y": 0.3 }, { "id": "n2", "label": "B", "x": 0.6, "y": 0.6 } ],
  "pairs": [ ["n1", "n2"] ]
}
```

`pairs` 中每对节点需依次点选完成连线，全部连对即通关。

**⑤ `drop` —— 拖到判定区**（如：黑洞引力）

```json
{
  "ball": { "id": "b1", "startX": 0.2, "startY": 0.5 },
  "target": { "x": 0.8, "y": 0.5, "radius": 0.1 },
  "tolerance": 0.05
}
```

#### 前端实现要求

- 实现一个 `interactionConfig` **解释器组件**，按 `type` 分发到五个子组件
- **不通关不给星**；失败可重试，不扣进度
- 通关后调 `progress` 云函数的 `complete`（**奖励判定在云函数，前端只做展示**）
- 载荷上限：`interactionConfig` 序列化后 **≤ 8 KB**（云数据库单文档限制的保守值）
